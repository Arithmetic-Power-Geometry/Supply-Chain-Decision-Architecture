# Comparator Framework Freeze Protocol v1

Comparator frameworks are selected from genuine SCM literature before headline SCDA model results are inspected.

A comparator must have a verifiable scholarly source and a sufficiently explicit representation to permit reproducible mapping. Framework names, dimensions and mapping rules are recorded from source evidence; missing dimensions are not inferred merely to make comparison possible.

The comparison distinguishes the framework's native unit of representation from the SCDA claim-level representation. Any crosswalk is documented as an analytical mapping rather than presented as the source authors' terminology.

Comparator inclusion is based on relevance to SCM decision representation, process/reference architecture, planning hierarchy, solution/method classification, evidence representation, or context representation. Frameworks are not selected because they are expected to perform poorly.

Before model competition, freeze:
1. comparator identity and source;
2. native dimensions;
3. unit of representation;
4. crosswalk rule;
5. known non-comparable elements;
6. handling of missing/implicit fields.

Headline comparison may proceed only after this file is frozen. Results cannot be used to retroactively redefine a comparator.
